# OpenT5 0.2.0

Convert PC Mod Tools maps into working PS3 map zones, edit and patch zones, search
across every zone, and view models and worlds with their own textures.

## Custom maps

`opent5 convert` turns a map built with the PC Mod Tools into a PS3 map zone, either
replacing a stock map or under its own name with its own files. A converted map carries
its own lighting (lightmaps, light grid, reflection probes), its own compass, its own
materials and textures (including art that exists in no stock zone), static-model props,
the objective entities every multiplayer gametype needs, and a connected path-node graph.
Stock zones and paks are never modified: everything a map needs lives in its own files.

What makes a converted map load and play:

- **Path-node links are baked by the converter.** The retail engine reads baked path-node
  links; it does not connect nodes at load, and the Mod Tools "Connect Paths" step runs the
  PC game, which the toolchain here does not. So a map we build would ship no links and the
  engine would drop it at load ("Path nodes are not connected"). The converter now bakes the
  links in the stock PathData format as a single connected component, which is what lets a
  converted map load in every mode. A real map keeps its own baked links.
- **Search and Destroy plant triggers.** Bomb sites use the exact stock mp_nuked bombzone
  entity set (trigger_use_touch plant and defuse triggers, the bomb script_model chaining
  them, solid script_brushmodels), so the hold-to-plant prompt appears at each site.
- **Prop and bomb-site collision.** A static prop and each bomb site get a clip volume
  compiled into the BSP, so you cannot walk through them.
- **Path nodes by default.** The map generators emit a node_pathnode grid by default, so
  Domination and the other team-based modes have the connectivity they need.

## 3D viewer

The model and world viewer draws with the assets' own textures and lighting, with static
models on by default. Reworked camera controls: zoom to the cursor and through the pivot,
consistent pan speed, a Radiant/Unreal fly mode (hold right mouse to look, WASD to move,
Q/E down/up, scroll to change speed, Shift to go faster), double-click to focus a surface,
F to frame the selection and Home to frame all, with an on-screen controls hint. A
performance pass caches the render framebuffer across frames.

## Editing, patches, search, textures

- Nested struct fields are editable in the app and on the command line.
- Streamed textures can be replaced at a different size, not only the same size.
- `replace --allow-shared` edits images whose data lives in a shared pak, with a warning.
- **Mod patch format** (`opent5 patch create/apply/info`): share a mod as the difference
  from a stock zone, so no game files are redistributed; apply refuses a mismatched source.
- **Global search** (`opent5 search`, GUI "All Zones"): names and text across all 178 zones
  from a cached index.
- **Texture pack** (`opent5 texpack`): batch-replace a zone's textures from a folder of PNGs.
- **GUI polish:** structured error dialogs, empty states, a full keyboard list, both themes.

## Converter hardening

- The converter refuses to write a zone it cannot reproduce: if the PC zone does not parse
  exactly it fails with a clear message and writes nothing.
- The clipMap RUNTIME rope pool stride is confirmed (0xC74, the same on PC and PS3); stock
  zones and the first map with ropes both reserve exactly at it.

## Known limitations

- Prop collision is clip brushes compiled into the BSP, not per-model static-model collision
  in the clipMap. Props are solid where they stand; moving a prop would not move its
  collision (the in-place editor in v0.3.0 adds real static-model collision).
- A few baked path-node links can graze a solid: links are generated by distance, without a
  line-of-sight test against collision yet. This does not stop a map loading; it only means
  the AI could path through a small solid.
- No sky or sun on a generated outdoor map with this Mod Tools install: it ships no sky
  techset, so such a map is sealed and lit by placed lights.
- One wall texture can read mirrored on a face (a UV or tangent handedness flip on some
  converted gfx faces), still to be fixed.
- Edited zones keep the original console signature, which no longer matches, so they load
  only on a client with the signature check patched out.

The blocky (voxel) terrain map is not part of 0.2.0: it builds through the PC tools, but its
zone does not yet parse exactly in the converter (a gfx_map RUNTIME gap), so it is not
shipped.
