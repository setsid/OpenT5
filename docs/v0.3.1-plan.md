# v0.3.1 plan: editor refinements and deferred work

0.3.0 shipped the in-place map editor (select, move, rotate, add, delete, duplicate props,
spawns, objectives and lights; real clip collision; edit-relative path-link regen on save;
output to new files; verify on save) and the brand, splash and busy overlay. These are the
refinements and deferred items noted during 0.3.0, grouped by theme, roughly in priority order.

## Editor usability

- **Gizmo feel on a real GPU.** The drag/rotate maths are tested headlessly; tune the on-screen
  gizmo size, hit tolerance and drag sensitivity from hands-on use. Consider a screen-space
  constant gizmo size and clearer axis handles.
- **Multi-select and box-select**, with a single move/rotate over the set.
- **Snapping defaults and a visible snap readout.** Grid and angle snap exist in the panel;
  surface the current snap on screen and pick sensible defaults (for example 8 units, 15
  degrees).
- **Prop vs entity legibility.** Props are now a brighter diamond; add per-type colours/icons
  and a hover highlight so a click target is obvious before clicking.
- **Undo scope.** Decide and document whether undo is per-zone-tab or global, and make the
  Undo/Redo buttons reflect the active scope.

## Collision and rotation

- **Oriented prop clips.** Non-axial rotation currently keeps an axis-aligned clip box. Build an
  oriented (sided) clip, or rebuild the cluster the cod2map way, so a rotated prop's solid
  volume turns with it.
- **Per-instance triangle picking.** Picking is bounds-level (a prop is a box). If the merged
  mesh can be indexed per instance, refine picks to the triangles for tight selection of thin or
  overlapping props.

## Lighting (the enabler for several items)

- **Relighting.** The single biggest limit: the editor cannot relight, so a moved or deleted
  prop leaves its baked lightmap shadow, and sun edits read as broken. Investigate an offline
  relight (even a coarse one) or re-running cod2rad on an edited map. Relighting unlocks:
- **Sun editing** (deferred in 0.3.0; it only drives the real-time sun today).

## Fog and scripting

- **Fog editing** via the map's GSC tweakfile (`scr_fog_*`, `setVolFog`), if we add GSC rawfile
  editing. Fog is script state, not a gfx_world field (see docs/research/sun-fog.md).
- **GSC injection in the converter.** Would unlock map-script features that are impossible today:
  jump pads, a teleporter pair, a moving platform/lift, doors. Turrets remain blocked unless an
  MP weapon asset can be supplied. Device-tested, separate effort.

## Paths

- **A proper offline Connect-Paths.** Our line-of-sight connectivity model is stricter than the
  engine's (retail reads as several components yet loads fine, see
  docs/research/pathlink-los-recipe.md). A faithful link generator would let us author
  connected graphs for maps that ship without baked links.

## Blocky map track

- **o_blocks5 polish.** Interiors, stairs, ladders, the lava perimeter and the clip wall are in;
  refine terrain variety and building layout from device feedback.
- **Emissive lava** if a self-illum techset can be found in a fuller Mod Tools install (today it
  is a flat lava-coloured tile). **A real skybox** likewise needs a sky techset.

## Build, tooling and tech debt

- **CI for the one-file exe.** The 0.3.0 one-file failures came from building against a polluted
  interpreter; `build.bat` now guards against it, but a CI build + windows-platform smoke would
  catch it automatically.
- **verify_staged_map for clip-only builds.** The staged-map gate compares gfx/clip counts and
  bounds, so it cannot tell a clip-move build from the base. Add a clip-position signature.
- **Fix the parked box-map entity test.** `test_convert_entities::test_compiled_box_matches_the_generator`
  fails on v0.3.0 (pre-existing, box-map entity path; see docs/parked.md).
- **Lint and format pass.** `ruff check src tests tools` has pre-existing errors (mostly in
  `tools/`); clear them and consider enforcing `ruff format`.
